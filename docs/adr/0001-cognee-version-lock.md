# ADR 0001: Cognee 大版本锁定策略

**状态**: 提议中  
**日期**: 2026-08-02  
**决策者**: 工程讨论

---

## 背景

Cognee 当前版本为 1.x，其内部 API（如 `DataItem`、图引擎、cognify 流程）频繁变动。适配层直接依赖这些内部接口会随 Cognee 升级而断裂。

## 决策

对 Cognee 做 **大版本锁定**：

1. `pyproject.toml` 中标注 `cognee>=1.4,<2.0`（约束在主版本范围内）
2. CI 中配置定期触发（周级）的集成测试，检测最新 Cognee 1.x 是否兼容
3. 当 Cognee 发布 2.0 时，需人工评估并更新约束
4. README 中明确标注兼容的 Cognee 版本范围

## 备选方案及理由

| 方案 | 判断 |
|------|------|
| 不锁版本 | 用户安装可能拉到不兼容的最新版，代价太高 |
| 完全隔离 Cognee API（做抽象层） | 工程量太大，且 Cognee 1.x API 核心接口（`remember/recall/forget`）已趋于稳定 |
| 精确锁定 `==1.4.1` | 过于严格，用户无法使用 1.4.x 的修复版本 |

**选择「主版本范围约束」**——平衡了兼容性和灵活性。

## 后果

- 适配层可以安全使用 Cognee 1.x 的公共 API 和部分稳定的内部接口
- 当 Cognee 2.0 发布时需人工评估，这是已知的维护窗口
- CI 中需要集成测试覆盖，防止 Cognee minor 升级导致的静默破坏
